LumenStay Engineering Architecture

Multi-property guest experience, real-time property management system (PMS), and automated revenue platform designed for Lumen Hospitality Group LLC.

01

System Architecture & Component Diagram

LumenStay implements a strictly-typed, decoupled full-stack architecture. The frontend is powered by React 18 + Vite with Tailwind CSS and Framer Motion micro-animations. The backend is an Express + TypeScript API Gateway enforcing unified JSON envelopes, centralized error trapping, and atomic database transactions.

03

Database Schema & Data Dictionary

Target PostgreSQL DDL definitions with check constraints, foreign keys, and indexes:

PostgreSQL / Supabase Schema Definition
-- Core Schema with Referential Integrity
CREATE TABLE properties (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  slug TEXT NOT NULL UNIQUE,
  tagline TEXT NOT NULL,
  city TEXT NOT NULL,
  state TEXT NOT NULL,
  phone TEXT NOT NULL,
  email TEXT NOT NULL,
  brand_theme JSONB NOT NULL,
  amenities JSONB NOT NULL DEFAULT '[]'::jsonb,
  total_rooms INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE room_types (
  id TEXT PRIMARY KEY,
  property_id TEXT NOT NULL REFERENCES properties(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  code TEXT NOT NULL,
  base_price NUMERIC(10, 2) NOT NULL,
  capacity_adults INTEGER NOT NULL DEFAULT 2,
  bed_configuration TEXT NOT NULL,
  size_sq_ft INTEGER NOT NULL,
  total_inventory INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE rooms (
  id TEXT PRIMARY KEY,
  property_id TEXT NOT NULL REFERENCES properties(id) ON DELETE CASCADE,
  room_type_id TEXT NOT NULL REFERENCES room_types(id) ON DELETE CASCADE,
  room_number TEXT NOT NULL,
  floor INTEGER NOT NULL DEFAULT 1,
  building TEXT NOT NULL DEFAULT 'Main Lodge',
  status TEXT NOT NULL DEFAULT 'clean' CHECK (status IN ('clean', 'dirty', 'inspected', 'out_of_order')),
  quirks TEXT,
  is_occupied BOOLEAN NOT NULL DEFAULT FALSE,
  UNIQUE (property_id, room_number)
);

CREATE TABLE reservations (
  id TEXT PRIMARY KEY,
  confirmation_code TEXT NOT NULL UNIQUE,
  property_id TEXT NOT NULL REFERENCES properties(id),
  guest_id TEXT NOT NULL REFERENCES guests(id),
  room_type_id TEXT NOT NULL REFERENCES room_types(id),
  assigned_room_id TEXT REFERENCES rooms(id),
  rate_plan_id TEXT NOT NULL REFERENCES rate_plans(id),
  status TEXT NOT NULL DEFAULT 'confirmed' CHECK (status IN ('confirmed', 'checked_in', 'checked_out', 'cancelled', 'no_show')),
  check_in_date DATE NOT NULL,
  check_out_date DATE NOT NULL,
  total_amount NUMERIC(10, 2) NOT NULL,
  paid_amount NUMERIC(10, 2) NOT NULL DEFAULT 0,
  digital_key_issued BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE folio_charges (
  id TEXT PRIMARY KEY,
  reservation_id TEXT NOT NULL REFERENCES reservations(id) ON DELETE CASCADE,
  property_id TEXT NOT NULL REFERENCES properties(id),
  category TEXT NOT NULL CHECK (category IN ('room_rate', 'tax', 'resort_fee', 'minibar', 'dining', 'spa', 'parking', 'late_checkout', 'adjustment', 'payment')),
  description TEXT NOT NULL,
  amount NUMERIC(10, 2) NOT NULL,
  status TEXT NOT NULL DEFAULT 'posted' CHECK (status IN ('posted', 'void', 'paid')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- B-Tree Performance Indexes
CREATE INDEX idx_reservations_dates ON reservations (property_id, room_type_id, status, check_in_date, check_out_date);
CREATE INDEX idx_rooms_lookup ON rooms (property_id, room_type_id, status);
CREATE INDEX idx_folio_res_id ON folio_charges (reservation_id);

Transactional Booking & Concurrency Model

To prevent double bookings during simultaneous checkout requests, the booking engine executes availability checks and inventory writes within an atomic transaction.

Date-Range Overlap Condition:
Overlap = (Existing.CheckIn < Requested.CheckOut) AND (Existing.CheckOut > Requested.CheckIn)

AND room_type_id = $2
AND status IN ('confirmed', 'checked_in')
AND (check_in_date < $checkOut AND check_out_date > $checkIn) DB-->>Service: bookedCount = N Service->>DB: SELECT total_inventory FROM room_types WHERE id = $2 DB-->>Service: totalInventory = M alt bookedCount >= totalInventory Service->>DB: ROLLBACK TRANSACTION Service-->>Controller: Throw ApiError(409, "Fully Booked") Controller-->>User: 409 Conflict Response else bookedCount < totalInventory Service->>DB: INSERT INTO guests (...) ON CONFLICT DO UPDATE Service->>DB: INSERT INTO reservations (...) Service->>DB: INSERT INTO folio_charges (...) Service->>DB: COMMIT TRANSACTION Service-->>Controller: return Reservation Controller-->>User: 201 Created ApiResponse end
